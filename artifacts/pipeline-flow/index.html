대화·기억 전체 흐름 — 내 친구 민수

가입 이후 하나의 채팅방이 이어지는 방식, 첫 안부, 일반 답변, 과거 대화 확인, 기억을 고치거나 지운 뒤 연결을 다시 만드는 흐름을 현재 코드 기준으로 나눠 그렸습니다.

스페이스 일시정지 · R 다시 · S 저장

하나의 채팅방과 사람처럼 작동하는 기억

  1. 가입과 함께 한 방 시작작업 상태 id는 <user_id>-main 하나
  2. 모든 원문 영구 저장PostgreSQL에 문장·순서·시각 보존
  3. 최근 흐름만 평소에 읽기JSON 작업 기억과 관련 온톨로지
  4. 오래된 흐름은 압축최근·위기·핵심은 보호, 원문은 불변
  5. 사용자가 확인을 요구“전에 말했잖아”, 날짜 질문 등
  6. 원문을 검색해 회상LLM 아닌 날짜·키워드 검색
  7. 짧게 답하고 돌아오기서비스 안내·불필요한 허락·억지 질문 없음

채팅창을 열었을 때

  1. 실제 마지막 대화 시각 확인저장 작업 시각은 제외
  2. 간격·사용자 시간대 계산첫 방문·같은 날·다음 날·3일·1주
  3. 첫 안부 한 번 생성시간은 소재 후보일 뿐, 정해진 문구 없음
  4. 문장 전체의 온기·거리감 검수생성된 모든 첫말을 한 번 확인
  5. 필요할 때 한 번만 다시 쓰기알려진 어색한 표현은 코드에서도 차단
  6. 첫말 저장·화면 표시하나의 영구 채팅방에 이어서 추가

도식은 좌우로 밀어 볼 수 있어요.

기억을 고치거나 지웠을 때

  1. 독립 웹 작업면 열기앱 모달이 아닌 넓은 온톨로지 그래프
  2. 기억 노드 선택전체 문장·공개 범위·수정·삭제
  3. 수정 또는 삭제 확정관계 재연결 또는 철회 상태 저장
  4. 남은 활성 트리플 재조회Entity–Statement–Entity 그래프 재배치
  5. 낡은 세션 배경 비우기삭제한 기억의 사본 차단
  6. 최근 대화 재큐레이션필요→확장→조회→충분성→톤

시각 그래프 재배치는 코드가 맡습니다. 여러 모델 호출이 필요한 Agentic RAG는 바뀐 기억의 검색 후보와 대화용 톤을 다시 고르는 단계이며, 실패해도 앞에서 확정한 수정·삭제는 되돌리지 않습니다.

0. 과거 대화 확인 게이트

  • 평소: 원문 전체를 읽지 않고 그대로 통과한다.
  • 확인 요청: 사용자 원문만 날짜·키워드로 검색한다. LLM 없음.
  • 검색 중: 현재 문장에 맞는 짧은 확인 말을 한 번 보여준다.
  • 병렬 실행: 원문 검색과 짧은 확인 말은 서로 결과를 읽지 않아 동시에 시작한다.
  • 없거나 불확실: 기억하는 척하지 않고 언제 말했는지 묻거나 다시 얘기해 달라고 한다.

1. 기억 주입 게이트

  • 하는 일: 답 만들기 전에, 이 사람 기억 중 이번 프롬프트에 넣을 것만 고른다. LLM 없음.
  • 항상 넣음: 위기 기록, “먼저 꺼내도 됨” 기억, 정체성 한 줄(호칭 등).
  • 이번 말에 걸릴 때만: 열린 화제와 맞는 사실 원문.
  • 안 넣음: 잠금(quiet) 원문, 민감 정보 원문(위기 제외). 억제 = 아예 안 넣기.

2. 되물을지 판정 (decide)

  • 판단: 지금 바로 답해도 되는지, 아니면 먼저 한 줄 더 물어야 하는지.
  • 상황 되묻기: 언제·어디서·무슨 일이 통째로 비어 있을 때 → 질문만 하고 턴 끝.
  • 감정 되묻기: 일은 있는데 마음이 뭉뚱그려져 있을 때 → 감정 짚는 질문 후 끝.
  • 정체성 되묻기: 아직 모르는 호칭·하루의 모양·곁의 사람 등이고, 물을 타이밍일 때(후보 없으면 선택지 자체 없음).
  • 바로 답: 상황·감정이 이미 말 속에 있을 때 → 감정만 갱신하고 아래 단계로.
  • 코드 강제: 직전이 질문 턴이었거나, 위기 신호면 LLM 없이 바로 답 쪽(안내는 답변 경로에 실음).

3. 대화 방향 정리 (orient)

  • 판단: 이번 대화의 국면·흐름·다음 움직임과 응답 방식(공감/방법/둘 다)을 함께 정리한다.
  • 공감: 감정을 쏟아내고, 조언을 안 바란 말.
  • 방법: 어떻게 할지·다음 단계를 묻는 말.
  • 둘 다: 감정도 크고 다음 단계도 궁금할 때. 공감 뒤 방법으로 이어갈지는 연결 허용 여부가 결정한다.
  • 중복 방지: 감정 강도가 낮고 흐름이 악화되지 않은 직접 조언 질문은 방법 경로 하나만 실행한다.
  • 이어가기: 직전 대화 궤적, 감정 분석, 기억 속 “원하는 것”을 함께 본다.

4. 이번 턴 태도 (persona)

  • 판단: 공감/방법 무엇이 아니라, 어떻게 말할지만. (orient 다음에 옴)
  • 4턴 임대: 평범한 연속 턴은 직전 말투를 재사용하고 현재 next_move·금지만 합침.
  • 즉시 갱신: 첫 답·방향 전환·위기·거절·반박·새 경계·4턴 만료.
  • 유지: 사용자가 말한 경계·직전 금지는 재사용 중에도 바로 반영.
  • 막음: 이미 정한 분기(공감/방법) 자체를 금지 목록에 넣는 것.

5. 초안 작성 → 한 번 다듬기

  • 공감 초안 / 방법 초안: 각 경로가 첫 답을 씀.
  • finalize: 말투와 의도를 함께 보고 문제가 있는 부분만 최소 수정. LLM 1회.
  • 친구 말투 안전선: 상담식 거리 표현과 진행 보고 뒤 요청하지 않은 체크리스트를 코드로 다시 확인.
  • 위기 안전선: 상담 번호가 있는 초안은 모델이 문장을 보태도 검증된 초안을 유지.
  • 재호출 없음: 코드 검사에서 걸리면 안전한 짧은 반응으로 끝냄.
  • 둘 다: 연결이 허용됐을 때만 공감 확정 후 방법 초안·검수로 이어 붙임.

6. 응답 전송 뒤

  • 사용자는 이미 답을 받음. 아래는 대기 화면 밖에서 돈다.
  • 기억 만들기: 이번 대화에서 사실·정체성 슬롯 등을 뽑아 그래프 DB에 쌓음.
  • 원문 저장: 화면은 PostgreSQL의 영구 기록을 읽는다.
  • 작업 기억 압축: 4,000자를 넘으면 오래된 말을 줄인다. 원문은 건드리지 않는다.
  • 병렬 실행: 기억 만들기와 압축은 같은 스냅샷에서 동시에 계산한다.
  • 저장: 필드만 부분 갱신해서, 그 사이 지운 기억·다음 말이 덮이지 않게 함.
